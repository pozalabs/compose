# 에이전트용 패키지 인덱스 문서 (AGENTS.md) 동봉

## 목표

소비 프로젝트에서 작업하는 에이전트가 설치된 compose 버전과 항상 동기화된 "작업: 심볼" 인덱스를 로컬(.venv)에서 읽을 수 있도록 `compose/AGENTS.md`를 패키지에 동봉

## 상세

### 배경 결정

에이전트에게 패키지 사용법을 제공하는 정보를 세 층으로 나누고 각 층을 낡을 수 없는 위치에 배치한다는 방침에서 출발

- 계약(시그니처, 동작): 소스 + `py.typed` + LSP가 정본. 문서로 중복 기술하지 않음
- 관용구(조합 방식, 구조): 소비 프로젝트 측 글로벌 스킬(compose-ddd)이 담당
- 발견(어떤 작업에 어떤 심볼이 있는가): 이 스펙의 대상. 현재 README에 모듈 지도가 있으나 wheel에 실리지 않아 소비 프로젝트의 에이전트가 볼 수 없음

문서를 `compose/` 패키지 디렉토리 안에 두면 현재 빌드 설정(`[tool.hatch.build.targets.wheel] include = ["compose"]`) 그대로 배포되어 설치 버전과의 동기화가 구조적으로 보장됨 (`compose/py.typed`가 같은 설정으로 이미 동봉되고 있음)

### 정본과 이관 원칙

README는 이관의 출발점일 뿐 정본이 아님. README와 소스가 어긋나는 항목은 소스를 기준으로 교정하여 옮긴다. 작성 시점에 확인된 불일치:

- README 구조 섹션의 `dependency` 모듈은 실제로 `compose.di` (`compose/di/`). AGENTS.md에는 `compose.di`로 기재
- README 선택적 의존성 섹션의 "extras 패키지는 관리하지 않으며" 문구는 사실과 다름. `pyproject.toml`의 `[project.optional-dependencies]`에 12개 extras가 정의되어 있으며 이를 정본으로 삼음
- README에 없는 최상위 모듈 다수 (아래 "모듈 지도" 참조)

   - **모듈 지도**: "작업: 심볼" 형식. 항목 단위와 분류는 아래 "모듈 지도" 참조
   - **선택적 의존성**: extras명별로 활성화되는 모듈/심볼 리스트. 아래 "선택적 의존성" 참조
   - **추가 자료**: 리포에만 있는 자료의 GitHub 절대 URL 링크. 아래 "추가 자료" 참조

### 모듈 지도

**항목 단위**: 서브패키지 진입점 심볼. 즉 각 서브패키지 `__init__.py`가 재export하거나 `__all__`에 올린 클래스/함수만 개별 항목으로 실음. 진입점 밖의 심볼(예: `compose/query/mongo/op/` 하위 연산자 73개)은 개별 나열하지 않고 모듈 단위 한 줄로 안내. 단일 파일 모듈(`compose/dag.py` 등)이나 `__all__`이 없는 서브패키지(`di`, `lock`, `command`, `event` 등)는 모듈 단위 한 줄로 안내

**항목 형식**: `- <하고 싶은 것>: \`<모듈 경로 기준 심볼>\` (<extras명, 필요 시>)`. 한 항목이 여러 심볼을 가리키면 ` / `로 구분. 모듈 단위 안내는 심볼 자리에 모듈 경로를 적음

```markdown
### 영속성

- offset 페이지네이션 조회: `compose.query.MongoOffsetPaginationQuery` (mongo)
- 단순 필드 일치 조회를 선언적으로 정의: `compose.repository.finder` / `lister` (mongo)
- MongoDB 쿼리 연산자 조합: `compose.query.mongo.op` 모듈 (mongo)
- Entity 목록 응답: `compose.schema.ListSchema`
```

**분류**: README의 5개 분류를 유지하고 2개를 추가. `compose/__init__.py`의 `__all__`과 조건부 import 블록에 있는 모든 최상위 모듈이 아래 어딘가에 배치되어야 함

- 도메인 모델링: `entity`, `command`, `event`, `types`, `exceptions`, `model`(`BaseModel`, `TimeStampedModel`), `field`, `enums`
- 영속성: `repository`, `query`, `uow`, `pagination`, `schema`
- 메시징: `messaging`
- 인프라: `di`, `auth`, `settings`, `lock`, `logging`, `httpx`
- 프레임워크 통합: `fastapi`, `aws`, `otel`, `gunicorn`, `testing`, `testcontainers`
- 유틸리티 (신설): `asyncio`, `concurrent`, `dag`, `stream`, `func`, `utils`, `constants`, `typing`
- 위 배치는 제안이며 작성 시 모듈 내용을 보고 더 맞는 분류로 옮겨도 됨. 단, 누락은 불허

### 선택적 의존성

정본은 `pyproject.toml`의 `[project.optional-dependencies]`. 형식:

```markdown
- `mongo` (`uv add pozalabs-compose[mongo]`): `repository.mongo`, `query.mongo`, `uow.mongo`, `entity.MongoEntity`, `types.PyObjectId`, `lock.mongo`
```

- 12개 extras(`jwt`, `oauth`, `aws`, `dependency-injector`, `dishka`, `fastapi`, `httpx`, `loguru`, `mongo`, `otel`, `sentry`, `sql`)를 모두 나열
- 각 extras가 활성화하는 모듈/심볼은 해당 모듈의 import 가드(`try: import ... except ImportError`)를 소스에서 확인하여 기재. README의 기존 목록은 참고만 함
- extras로 정의되지 않은 선택적 의존성(`testing`은 `pytest`, `testcontainers`는 `testcontainers[mongodb]`)은 리스트 말미에 패키지명으로 별도 표기하고 extras가 아님을 명시

## 경계

- 항상: 심볼의 존재와 위치만 안내. 시그니처, 파라미터, 동작 설명은 소스에 위임
- 항상: AGENTS.md를 발견용 인덱스의 정본으로 유지. README에 모듈 목록을 다시 만들지 않음
- 항상: 인덱스에 적는 모든 심볼은 기재한 모듈 경로로 실제 import 가능한지 작성 시점에 확인
- 항상: README와 소스가 어긋나면 소스를 따름
- 절대: `examples/`, `docs/`를 wheel에 포함하지 않음
- 절대: AGENTS.md에 버전별 이력이나 마이그레이션 안내를 넣지 않음 (CHANGELOG 담당)

## 검증

- wheel 동봉 확인: `uv build` 후 `unzip -l dist/*.whl`에서 `compose/AGENTS.md` 존재 확인. 이 검증이 실패하면 빌드 설정이 md 파일을 제외하고 있다는 버그가 드러남
- 심볼 경로 확인: AGENTS.md에 기재한 모든 심볼/모듈 경로를 추출하여 전체 extras를 설치한 환경(`uv sync --all-extras`)에서 `python -c "import importlib; importlib.import_module('compose.query.mongo.op')"` 및 `from compose.repository import finder` 형태로 import 실행. 이 검증이 실패하면 인덱스가 존재하지 않거나 재export되지 않은 경로로 에이전트를 안내하는 버그가 드러남 (이름만 grep하면 `shortcut.py`의 정의는 찾지만 `__init__` 재export 누락은 놓치므로 import 실행이 필요)
- 최상위 모듈 누락 확인: `compose/__init__.py`의 `__all__`과 조건부 import 블록에 있는 모듈명이 모두 모듈 지도에 등장하는지 대조. 이 검증이 실패하면 에이전트가 발견할 수 없는 모듈이 있다는 버그가 드러남
- extras 정합성 확인: `[project.optional-dependencies]`의 12개 키가 선택적 의존성 섹션에 모두 등장하고 섹션에 그 외 extras명이 없는지 대조. 이 검증이 실패하면 존재하지 않는 extras나 빠진 extras를 안내하는 버그가 드러남
- 자동화 테스트는 두지 않음: 위 확인은 작성 시점 1회 수동 실행이며 이후 동기화는 운영 규칙(CLAUDE.md)으로 관리. 문서 파서 테스트는 비용 대비 가치가 낮다고 판단
